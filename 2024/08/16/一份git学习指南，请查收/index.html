一份git学习指南，请查收

git作为目前最广泛使用的版本控制工具，掌握git的使用应该是每个程序员的标配，尤其是在团队中工作时。但用好git很难，有时一不小心就出错了，因此了解git的工作流和命令非常必要。

本文中主要介绍git的工作流和常用命令，不涉及git的安装配置以及和GitHub远程仓库的连接，如有需要，可参考AI有道的这篇教程。

分布式版本控制

git是一个分布式的版本控制系统（简称VCS），区别于集中式VCS工具（如SVN）通过中央VCS服务器统一管理代码版本号，分布式VCS在服务端和客户端都有完整的版本库，客户端可以脱离服务器进行版本控制，系统会根据用户每次提交代码自动生成一个独一无二的版本号（Commit ID），这个过程由Hash算法实现，代码发生改变，版本号也会随之变化，反之，代码不变的话版本号也不会改变。因此客户端可以在不访问服务器、没有网络通信的情况下进行查看历史和版本⽐较等等操作，相比集中式VCS版本管理效率更高。

git工作流

git系统包含本地客户端和远程服务端，GitHub就是一个远程服务端。

git的本地客户端可分为三个区域：工作区（working space）、暂存区（stage）和代码仓库（history）。其中，工作区用于存放本地实际存在的文件；暂存区相当于本地git仓库的缓存区，临时保存待提交文件的改动；而本地仓库保存历史提交记录，并使用一个HEAD指针指向最新一次提交。

  • git add：将本地文件的修改提交至暂存区，处于工作区的文件会标记为untracked，添加至暂存区后用stage标记，可使用git status命令查看文件状态。

  • git commit：将暂存区的修改提交至本地仓库。提交记录保存的是文件快照，不是完全复制，与上一版对比的增量代码。提交后暂存区被清空，HEAD指向最新的提交记录。

  • git push：将本地仓库的提交记录推送至远程仓库也就是服务器端（如GitHub）。

  • git fetch：将远程仓库的最新记录拉取到本地仓库，但不会修改工作区。

  • git pull：相当于fetch+merge，将远程仓库的提交记录拉取至本地并和工作区修改记录合并。

学习工具

通过了解git的工作流我们已经掌握了一些命令，但仅仅掌握这些还不足以应对实际的应用场景，我们还需要进一步熟悉理解git的更多命令。这里推荐一个非常实用的学习工具：Learning Git Branching[1]，区别于其他教程，这个网站更像一个可以在线练习git的游戏，以动画的形式更加直观地展示各个命令的效果，更重要的是，可以帮助我们在头脑中建立“提交树”的概念，实测半天就可以通关。

通关记录

别忘了用好游戏网站自带的命令：

  • show goal：展示每一关的目标

  • objective：通关小提示

  • undo：撤销操作

  • show solution：查看答案

常用命令

我将git的命令分为本地命令和远程命令来记忆，本地命令操作的是本地仓库，与本地的工作流有关，远程命令则是操作远程仓库。

本地命令

主要为创建分支、合并、撤销、修改等操作。git add/commit等命令不再赘述。

创建分支

记住两个命令：checkout、branch。

  • git branch <分支名>：创建分支

  • git checkout <分支名>：切换到对应分支。——在 Git 2.23 版本中，引入了一个名为 git switch 的新命令，最终会取代 git checkout，因为 checkout 作为单个命令有点超载（它承载了很多独立的功能）。

  • 创建分支同时切换到该分支：git checkout -b <分支名>

合并分支

合并操作有两类——merge和rebase。

  • git merge <目标分支>：将目标分支合并到当前分支，HEAD指向当前分支合并后的最新记录。——过程更像是“拉取”。
  • git rebase <目标分支>：将当前分支的记录复制追加到目标分支最新记录之后，保持了原有线性顺序。——过程更像是“推送”。

merge和rebase各有优劣，rebase可以使提交树变得干净，所有记录都在一个分支上，但相应地，会改变提交的原有顺序，anyway，选择自己习惯的就好。

移动指针

前面提到，在本地仓库中有一个HEAD指针，该指针通常指向当前分支名从而指向当前分支的最新提交记录，那么是否可以让其与当前分支名分离呢？

——当然。

  • git checkout <记录哈希值>：让HEAD与当前分支名分离，指向哈希值对应的提交记录。git log可以查看提交记录的哈希值，仅需输入能够唯一标识提交记录的前几个字符。如果想查看HEAD指向，可以通过cat .git/HEAD查看。

当然也有不需要输入哈希值的方法，就是采用相对引用，即^和~两个符号。

  • git checkout <分支名或HEAD>^：向上移动一个记录，^^则是向上移动两个，^^^是向上移动三个……

  • git checkout <分支名或HEAD>~n：向上移动n个记录（n是正整数）。

如果想移动的不是HEAD而是分支名，让分支名指向其他的提交记录呢？

  • git branch -f <分支名> <记录哈希值或相对引用>：比如强制将分支main移动到当前提交的第三级父节点可采用如下命令：

git branch -f main HEAD~3

撤销记录

主要有两种方法用来撤销变更 ——git reset以及git revert。

  • git reset：通过把分支记录回退几个提交记录来实现撤销改动，本地代码库会不知道有原先的提交。reset之后，被撤销的记录将处于【未加入暂存区】的状态。

git reset HEAD~1 //回到当前分支的父节点

  • git revert：引入一个新提交记录，且新提交的更改是用来撤销上一个提交的。适合需要将改动推送到远程仓库的场景。

git revert HEAD   //注意和reset不一样，撤销最新提交不需要加相对引用

  • git reset --hard:添加–hard硬重置参数后，会回到上次commit的状态，也就是说从上次commit之后的的修改都将被重置。

整理提交记录

涉及两个好用的命令：git cherry-pick和git rebase -i，通过整理可以实现重排序、复制、删除等功能。

  • git cherry-pick <待抓取的记录哈希值>：将其他分支上的提交记录抓取到当前分支。可以抓取提交树任何地方的多个提交记录，只要不是 HEAD 上游的提交就没问题。

如果不记得哈希值，可以使用git rebase -i交互式方法。

  • git rebase -i HEAD~n：n为回溯步数，可以用来重排列前n个提交记录或者提取你想要的记录。

git rebase -i HEAD~4  //通过相对引用的方式指定提交记录的范围

远程命令

主要包括fetch、pull、push等命令。

分支对应关系

在git中，远程仓库的名字默认是origin，git工作流中存在三类分支：

  1. 本地分支——在本地仓库中创建的分支。可以用git branch命令查看本地所有分支，在git bash中一般显示为绿色且带*号。

  2. 本地远程分支——在本地仓库中标记远程仓库对应的更新位置，用于和远程仓库同步。可以用git branch -r查看远程所有分支，在git bash中一般显示为红色。

  3. 远程仓库分支——远程仓库中的分支，和本地远程分支一一对应。

以上图为例，左边的提交树属于本地仓库，右边对应远程仓库。左边提交树中的main和foo都是本地分支，o/main是origin/main的简写，是本地仓库中的远程分支，标记远程仓库中main分支的同步位置，右边提交树中的main则是远程仓库分支。

三种分支之间存在两种关系：

  1. 本地远程分支和远程仓库分支的关系。

  2. 本地分支和本地远程分支的对应关系。

本地远程分支o/main和远程仓库分支main是对应关系，o/main跟踪的本地的分支是可指定的，默认是绑定本地分支main，也可以绑定foo，有两种方法来指定：

//方法一：创建本地分支foo，使其跟踪远程分支origin/main git checkout -b foo origin/main //方法二：设置远程分支追踪，如果当前分支就是foo，命令可省略foo git branch -u origin/main foo

讲完git分支之间的对应关系，此时再看push、fetch、pull操作的参数就会更容易理解。

git push

git push <remote> <place>

remote指的是远程仓库，这里是origin，place参数是告诉git提交记录来自哪里，举个例子：

git push remote main

上述命令会自动将本地main分支的记录提交至远程仓库的main分支，如果想要提交到远程仓库的其他分支，可以通过指定源和目的地place的方式实现：

//其中，source为本地仓库中的位置，destination是远程仓库的位置 git push origin <source>:<destination> //举个有趣的例子 git push origin :foo //push空 到远程仓库，则会删除远程仓库分支foo

source和destination只要是git能识别的位置就行，比如分支名和相对引用。

git fetch

fetch的作用是将远程仓库分支下载到本地任意分支，命令格式如下：

git fetch <remote> <place> //举个例子：到远程仓库foo分支上，获取本地不存在的提交记录，放到本地远程分支origin/foo上 git fetch origin foo  如果不加参数，则会下载远程仓库中所有的提交记录到本地的各个远程分支。

fetch也可以像push那样指定源和目的参数：

//source为远程仓库中的位置，destination是本地仓库的位置,注意：和push参数是反的！ git fetch origin <source>:<destination> //举个有趣的例子：fetch空到本地 git fetch origin :bar //则会自动创建一个bar分支

git pull

pull的功能其实就等于fetch+merge，这一点在前面的git工作流中可以看出。fetch是将远程仓库的提交记录下载至本地仓库，但不关注最终合并到哪里，而pull则是将远程仓库的提交合并到工作区。

pull的命令参数和push、fetch一致：

git pull <remote> <place> //也可指定源和目的place，其中source是远程仓库位置，destination是本地位置 git pull origin <source>:<destination> //举个例子 git pull origin main:foo //从远程仓库main分支中下载提交记录，合并到本地foo分支，如果本地不存在foo分支，则创建一个。

更进一步的学习资源

到这里，已经讲完了git工作流中的常用命令，但是在实际运用过程中，可能会遇到很多复杂的问题场景，比如使用pull命令时，如果本地有未提交的修改，就会合并失败，因此真正理解git的工作流有助于我们解决此类问题。这里再推荐一个学习资源：oh shit git[2]，里面列举了一些我们可能会遇到的棘手的问题，并给出了处理的命令，可以作为一个小练手，巩固对git工作流的理解。

分支的处理是版本控制中非常重要的一环，尤其是参与团队的项目开发过程中，了解分支模型开发规范[3]也是很有必要的。
