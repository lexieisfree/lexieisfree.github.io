（二）⭐️类库的引用

软件的质量很大程度上取决于依赖关系，尽量使用弱依赖关系，更加清晰、易于维护。

使用类库就产生了依赖关系。

  • 类库引用是使用名称空间的物理基础。不同技术类型的项目会默认引用不同的类库。存在两种引用——DLL引用和项目引用。

DLL引用（无源代码，黑盒引用）

  1. 直接引用dll，一定要有相应的文档（说明包含的名称空间和类，以及类的方法）。

  2. 操作：引用-添加引用-浏览

  3. NuGet技术

  4. 解决的问题：如果只有DLL，蒙着眼睛引用类库，底层依赖不清晰，可能导致没完没了地添加引用。

  5. 思路：类库以包的形式发布到网上，一个命令直接引用一组类库。更加安全、高效

  6. 例子：Entity Framework实体框架类库

项目引用（有源代码，白盒引用）

  • 操作：先右键solution-add existing project，再添加引用

  • 一个项目隶属于不同的solution，称为项目的重用

  • solution和project的区别

  • solution是针对客户需求的总的解决方案，就像汽车经销商需要一套销售软件。

  • project解决具体的问题

自己建类库项目

  • 操作：右键solution-add new project-Class Library（不包含可执行程序）

  • 引用时在cs文件中添加相应的名称空间，调用方法时 “类名.方法名”

依赖关系（类或对象之间的耦合关系）

  4. 变量一共有7种：静态变量、实例变量（非静态成员变量、字段）、数组元组、值参数、引用参数、输出参数、局部变量。

P8-P9 方法的定义、调用与调试

（一）方法的由来

  1. 方法（method）的前身是C/C++语言的函数（function）

    C++扩展了面向对象特性，同时又保留了C的特性，可以兼容C。

    在C++中，可以在类之外创建函数，也可以在类中创建函数（也就是方法）。

    在C++中创建一个类时，会生成两个文件，分别是.h和.cpp，.h中是对类的声明，.cpp中是对类的定义，C#中声明与定义不分家。

    C#、Java语言是纯面向对象语言，方法必须隶属于类。

    当函数以类的成员形式出现时就成了方法。——函数到方法的过渡

  • 引用标准库使用尖括号：#include

  • 引用自定义库使用双引号：#include "Student.h"

  1. 方法是面向对象范畴的概念，在非面向对象语言中仍然称为函数。

  2. 函数是如何演变成方法体的？

  3. 方法永远是类（或结构体）的成员

  4. C#语言中函数不能独立于类（或结构体）之外。

  5. 只有作为类（或结构体）的成员时才能被称为方法。

  6. C++中是可以的，被称为全局函数。

  7. 方法是类（或结构体）最基本的成员之一

    面向对象语言将变量和函数封装为字段和方法，使它们变得更好理解、更好管理，能够比较自然地反映现实世界中事物运作的规律，这样写大型程序就不容易乱。

  8. 方法表示类（或结构体）“能做什么事情”。

  9. 最基本的成员只有两个——字段与方法（即成员变量与成员函数），本质还是数据+算法。

（四）方法的重载

  1. 首先对方法的重载有一个感性的认识。

Console.WriteLine(); //有十多个重载，可输出不同类型的值

  1. 重载的具体定义

  2. 为一个类创建方法时，方法名字可以相同，但方法签名不能相同，签名是用于表示唯一性的。

  3. 方法签名（method signature）由方法的名称、类型参数的个数和它的每一个形参（按从左到右的顺序）的类型、种类（值、引用或输出）组成。方法签名不包含返回类型。

  4. 实例构造器也可以重载。实例构函数签名由它的每一个形参（按从左到右的顺序）的类型和种类（值、引用或输出）组成。

  5. 重载决策（到底调用哪一个重载）：用于在给定了参数列表和一组候选函数成员的情况下，选择一个最佳函数成员来实施调用。——编译器自动选择。

  8. 观察局部变量的值与变化。使用Locals窗口，如果值变化了会变成红色。或者将鼠标放到局部变量上也会显示值。

（六）方法的调用与栈的（映射）关系

⭐️方法调用时栈内存的分配

  • 对stack frame的分析

  • 调用者称为主调者（Caller），被调用的方法称为被调者（Callee），主调者在调用被调者时，向被调者传参数，在C#和C++语言中，参数由主调者“管理”——由主调者负责将参数压入栈中以及从栈中清退。

  • 一定要看视频讲解！刘铁猛老师用excel讲解方法调用时栈的内存分配，非常形象直观。

  • 在栈中，每个函数都有自己的stack frame（栈帧）。一般函数的入口是Main函数，在Main函数中调用其他函数，因此Main函数以及它负责的变量（比如调用其他函数时传的参数）会首先压入栈中，这些栈空间都由Main函数管理。然后按照调用关系依次将其他函数及负责的变量压入栈中。

  • 被调者的返回值存在哪里？——CPU寄存器中，如果CPU寄存器存不下会另外在栈上开辟空间。

  • 当函数返回时，Callee的stack frame被清空，返回值从CPU寄存器存储到主调函数的局部变量中。按照调用关系依次清空各层被调者的栈空间，直到Main()函数也从栈中清空。

  • 栈溢出（stack-over-flow）指的是调用方法层级过深，而又没有返回，一层层往下延伸压入栈中，直到栈空间溢出。

P10-P12 操作符详解

操作符、表达式、语句都是为方法服务。

（一）操作符（perator）概览

  • 操作符个数是衡量一个编程语言是否强大的重要指标。操作符越多，基本运算能力越强大，组合复杂运算逻辑也越方便。

  • 被操作符操作的数据称为操作数（operand）。

（二）操作符的本质

  • 操作符的本质是函数（即算法）的“简记法”。

假如没有发明x，只有Mul函数，那么算式3+4×5只能写成Add(3, Mul(4,5))。

  • 操作符不能脱离它关联的数据类型

  • 示例：为自定义数据类型创建操作符，使用operator关键字创建GetMarry操作符

（三）操作符的优先级

  • 可以使用圆括号提高被括起来的表达式的优先级。

  • 圆括号可以嵌套。

  • 不同于数学，方括号[]和花括号{}在C#中有专门的用途。

  • []用来访问索引器，如访问数组元素。

  • {}用来表示名称空间、类、方法体的范围。

（四）同优先级操作符的运算顺序

  • 除了带有赋值功能的操作符，同优先级的操作符都是由左向右进行运算；

  • 带有赋值功能的操作符的运算顺序是由右向左；

  • 与数学运算不同，计算机语言的同优先级运算没有“结合律”，比如 3+4+5不能理解为Add(3,Add(4,5))。

checked与unchecked

  • 作用：检查值在内存中是否有溢出。数据类型标识一个数据类型的实例在内存中能占多大空间，超过该范围，就产生了溢出。checked告诉编译器检查是否有溢出，而unchecked则告诉编译器不用去检查。

uint x = uint.MaxValue; Console.WriteLine(x); string binStr = Convert.ToString(x, 2); Console.WriteLine(binStr); try {     uint y = checked(x+1);//C#默认采用unchecked模式，如果不加checked则输出0，且不会抛出异常；如果想要不检查，则在try代码块之外加unchecked{};     Console.WriteLine(y); } catch(OverflowException ex) {     Console.WriteLine("There's overflow!"); }

5.3 算数运算操作符（* / % + -）

  • 任何一个操作符都与其数据类型相关。算数运算操作符基本与数学中相同（数学中没有取余%），但当其操作的数据类型不同时，行为也不太一样。

  • 在进行数值运算时，要留心“数值提升”，数据类型提升，整数*double类型默认转换为double类型，这样就不会丢失精度。

5.6 逻辑与&、异或^、或|

  • 因为是用来操作数据的二进制结构，因此又称为 位与/位异或/位或。

  • & 相同为真1，不同为假0；

  • ^ 相同为假，不同为1；

  • | 只要有一个为真即为真。

5.7 条件与&&、条件或||

  • 与逻辑与或的区别：条件与或用于操作布尔类型值，在编程中使用更广。

  • 条件与或的短路：

  • &&：当发现左边的表达式已经为假的时候，右边的表达式就不会被执行。

  • ||：当发现左边的表达式已经为真的时候，右边的表达式就不会被执行。

int x = 5; int y = 4; int a = 3 if(x>y || ++a > 3 ) {     Console.WriteLine("Hello") } Console.WriteLine(a);
